# FE #53 주크박스 데이터·동기화

룸 화면에 `RoomJukeboxProvider`를 연결했다. `useRoomJukebox()`가 제공하는
`state`, `role`, `loading`, `pending`, `error`, `controlError`, `connectionError`,
`refresh()`, `control(command)`를 후속 오디오·주크박스 UI에서 사용한다.

`state`에는 BE #46의 음악 ID, `playing`·`paused`·`stopped`, 기준 위치,
서버 변경 시각, 반복 여부를 그대로 보존한다. 활성 역할이 있고 `state = null`이면
아직 음악을 선택하지 않은 룸이다. 역할이 없으면 접근할 수 없는 상태이며 기존
음악 상태를 제거하고 구독을 해제한다. 음악 제목과 DB 재생 시간은 후속 마스터
음악 목록에서 기존 음악 라이브러리를 사용한다.

제어 명령은 `play`의 음악 ID·선택 위치·반복, `pause`, `resume`, `stop`,
`seek`의 위치, `set_loop`의 반복 여부다. 마스터만 호출하며 최종 권한 검증은
BE RPC가 수행한다. 음량·음소거·signed URL·실제 오디오 위치 계산은 이후 TODO의
범위다. 클라이언트에는 기존 Supabase anon client만 사용한다.

현재 로그인 사용자의 활성 룸 구성원 역할과 주크박스 상태를 함께 조회한다.
룸 입장, 첫 구독·재구독 완료, INSERT·UPDATE 이벤트, 탭 활성화, 네트워크 복구,
Auth 변경 및 제어 완료 시 다시 조회한다. Realtime 이벤트를 조회 무효화에
사용해 상태와 현재 권한을 함께 확인한다. 늦게 도착한 이전 조회 결과는 무시하며,
룸 변경·로그아웃 중 완료되는 이전 제어 요청은 상태를 복원하지 않는다.

조회 실패 시 이전 상태를 제거하고 오류를 전달한다. RPC 오류 뒤에도 현재
권한을 다시 확인한다. 실시간 구독 실패는 별도로 전달하며 재구독 성공 시
해제한다. 닫힌 채널은 제거하고 다음 온라인·탭 복귀·수동 조회에서 새로 구독한다.
룸별 Provider key와 effect 정리로 구독·Auth 구독·이벤트 listener를 정리한다.

현재 BE는 본인의 퇴장 상태 변경을 직접 수신하는 Realtime 채널을 제공하지
않는다. 퇴장·강제 퇴장은 다음 재조회에서 확인해 구독을 정리한다. 후속 오디오
작업은 signed URL 재발급 거부 시에도 재생을 종료하고 상태를 다시 확인한다.

## 오디오 재생·위치 보정

Provider는 룸마다 하나의 `HTMLAudioElement`와 `startJukeboxAudio`를 관리한다.
`useRoomJukebox()`에 `audio` 상태와 `activateAudio()`, `retryAudio()`,
`setVolume(0..1)`, `setMuted(boolean)`을 추가했다. 조작 화면은 후속 TODO에서
이 인터페이스를 연결한다.

오디오 활성화 전에는 파일 메타데이터와 위치만 준비하고 소리는 출력하지 않는다.
활성화 동작은 준비된 오디오에서 사용자 이벤트 안에 `play()`를 호출한다.
브라우저가 거부하면 `needsActivation`을 다시 설정하며 공용 상태 동기화는 계속한다.
메타데이터 준비 전 활성화했거나 브라우저가 재생을 다시 차단하면 추가 활성화가
필요할 수 있다. UI는 `audio.loading`과 `audio.needsActivation`을 표시한다.
[브라우저 play 정책](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/play)을 따른다.

재생 위치는 서버 기준 시각 이후 경과 시간에 기준 위치를 더해 계산한다.
파일 로드 후 `audio.duration`으로 확인한 실제 길이를 사용해 한 곡 반복 위치를
계산하며, 반복하지 않는 파일 끝에서는 정지한다. DB 메타데이터의 재생 시간은
목록 표시용이며 오디오 위치 계산에 사용하지 않는다. 상태 변경·재조회·파일
로드 때 위치를 보정하며, 재생 중 작은 차이는 0.25초까지 허용한다.

음악별 signed URL을 발급하고 만료 시 다시 발급한다. 재발급 동안 재생을 멈추고
새 파일 메타데이터를 읽은 뒤 현재 서버 위치로 재개한다. 401·403 거부는 즉시
파일·재발급 타이머를 해제하고 룸 권한을 다시 조회한다. 기존 URL의 Storage
만료 정책은 BE 계약 그대로이며 클라이언트가 URL 자체를 취소하는 것은 아니다.

음악 변경·공용 정지·음악 삭제·접근 권한 상실·화면 해제 시 이전 오디오를 정리한다.
이전 URL 응답·재생 Promise는 이후 음악이나 해제된 룸에 반영하지 않는다.
파일 로딩·디코딩·재생 길이·URL 발급 오류를 전달하며 명시적 재시도로 다시 로드한다.
기기 음량·음소거는 음악 변경 후에도 유지하고 공용 상태에 저장하지 않는다.
