# 개인·룸 공용 자산 조회 (FE #3)

`/assets`의 기존 내 자산·개인 폴더 화면 아래에 룸 공용 자산 목록을 표시한다.
룸 목록은 `rooms`의 활성 구성원 RLS로 제한하고, 선택한 룸의
`room_asset_shares`에 연결된 자산만 조회한다. 공용 목록의 자산에는 소유자 구분을
표시하고 폴더 이동 등 개인 자산 관리 폼을 제공하지 않는다.

공유 이미지 요청은 현재 사용자 JWT와 anon key를 사용하는 인증 Storage
다운로드이며 `cache: "no-store"`로 요청한다. signed URL은 사용하지 않는다.
표시용 Blob URL은 룸 전환·새로고침·화면 종료 시 해제하고, 진행 중인 이전
룸의 요청도 취소한다. 공유 해제 후 새로고침하면 이전 목록과 이미지가 사라진다.
다른 구성원의 변경은 새로고침으로 반영한다.

BE #3의 공유 관계·메타데이터 및 인증 파일 다운로드 마이그레이션이 필요하다.
개인 자산 카드의 “공유 관리”에서 참여 중인 룸에 공유하거나 기존 공유를
해제한다. 이미 공유한 룸은 새 공유 선택지에서 제외하고, 현재 공유 범위에
룸별 해제 버튼을 표시한다. 참여하지 않는 룸의 기존 공유는 룸 ID로 표시하며
소유자가 해제할 수 있다. 공유 관계를 UPDATE하지 않고 INSERT·DELETE로 처리한다.

공유 관리 UI는 소유자 전용 개인 자산 목록에만 제공한다. 다른 구성원의 공용
자산에는 관리 버튼이 없으며, 최종 변경 권한은 BE RLS로 검사한다.
변경 후 공유 범위와 같은 화면의 공용 목록·참여 룸 목록을 다시 조회한다.
다른 구성원은 공용 자산 새로고침으로 변경을 확인한다. 단건 반환을 검사해
DELETE 0행을 성공으로 표시하지 않고, 중복·권한 변경·통신 오류를 안내한다.

## 검증

```sh
npm run test:assets
npx tsc --noEmit --incremental false
```

이미지 단위 테스트는 인증 헤더·캐시 차단·경로 인코딩·중복 요청 제거, 접근 거부,
요청 취소 시 Blob 생성 방지, URL 해제를 검사한다. 기존 업로드 검증·폴더 정렬·
이동 테스트도 함께 실행한다.

로컬 브라우저에서 다음 흐름을 확인했다.

- 구성원: 개인 자산과 다른 구성원의 공용 자산이 각각 표시되고, 공용 원본·
  썸네일이 로드된다. 공용 목록에 이동 폼이 없다.
- 룸 전환: 빈 룸 선택 시 이전 자산·이미지가 없어지고 빈 목록 안내가 나온다.
- 공유 해제: 다시 조회하면 해당 룸의 목록·이미지가 사라진다.
- 파일 조회 실패: 오류 안내가 나오고 이전 이미지를 표시하지 않는다.
- 비구성원: 참여 중인 룸이 없다는 안내가 나온다.
- 소유자 공유 관리: 두 룸에 공유하면 두 항목을 표시하고, 한 룸만 해제하면
  다른 룸 구성원의 이미지 조회는 유지된다. 같은 화면의 공용 목록은 자동 갱신된다.
- 비소유자: 개인 목록과 공유 관리 버튼에 다른 구성원의 자산이 나타나지 않는다.
- 중복 공유: 목록 조회 이후 다른 요청으로 공유된 룸에 재공유하면 중복 오류를
  안내하고 실제 공유 범위를 다시 표시한다.
- 이미 해제된 공유: 오래된 해제 버튼으로 DELETE 0행을 받으면 권한·상태 변경을
  안내하고 성공 메시지를 표시하지 않는다.
- 멤버십 변경: 목록 조회 이후 탈퇴한 룸으로 공유하면 권한 오류가 나고 참여 룸
  목록에서 제거된다. 탈퇴한 소유자는 기존 공유의 해제 버튼을 계속 사용할 수 있다.
